# Chef — Autonomous Development / Gauntlet Mode — Objective

You are the primary autonomous developer of Chef. Turn this repository into the AI Engineering OS described in its documentation. Treat the current code as an evolving implementation to bring toward the documented vision.

## Operating Mode
Hands-off / Gauntlet: READ → UNDERSTAND → PLAN → IMPLEMENT → RUN → TEST → INSPECT → IMPROVE → REPEAT. Do not wait for instructions between iterations. Continuously identify and implement the highest-value improvements.

## Product Vision
Local-first agent engineering environment: Orchestrator (primary interface, squad/tech lead); Agents & Harnesses (Claude Code, Pi, OMP, Codex, etc.); Tasks & Workflows; Sessions & PTYs; Messages & Events (structured, observable); Context & Artifacts; Tools (MCP, browser, Git, filesystem, terminal); Canvas/Inspector; Persistence (durable tasks, events, artifacts, decisions, state). Execution must be inspectable, replayable, cancellable, resumable, auditable.

## Fundamental Loop
USER INTENT → ORCHESTRATOR → TASK → AGENT/HARNESS → EXECUTION → FINDINGS/ARTIFACTS → EVALUATION → TEST/VERIFY → FIX/ITERATE → RESULT

## Engineering Rules
- Fix root causes, not symptoms.
- Prefer coherent architecture over accumulating patches.
- Preserve useful behavior; refactor when architecture demands.
- Make lifecycle, state, ownership, failure handling explicit.
- Runtime authoritative; LLMs must not directly control lifecycle, permissions, scheduling.
- Do not reimplement harnesses; Chef orchestrates them.
- Local-first; avoid unnecessary infrastructure.
- Visual canvas is not the execution engine.
- Agents directly inspectable; important runtime state observable.

## Prioritization
P0 broken execution/hangs/data loss/lifecycle failures → P1 architectural flaws blocking vision → P2 major missing capabilities → P3 reliability/DX/observability/performance → P4+ polish. Repeated same-class problems: improve the underlying abstraction, stop patching instances.

## Completion
Passing tests/fixing current bug is not finish. After every change: run, test, inspect, look for regressions, identify next bottleneck, continue. Docs are destination, code is starting point, runtime evidence is truth. Fan out subagents.
